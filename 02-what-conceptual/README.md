The Conceptual layer defines what STATE Engineering is independently of any particular workflow implementation or toolchain.

Its governing question is:

> **What concepts, properties and relationships must exist for a controlled STATE transition to be described and governed unambiguously?**

## Contents

1. [`01-the-state-model.md`](01-the-state-model.md) — authoritative, baseline, candidate, accepted, rejected and inconclusive state concepts.
2. [`02-foundational-properties.md`](02-foundational-properties.md) — the defining properties that must remain present for the method to retain its identity.
3. [`03-role-actor-capability-authority.md`](03-role-actor-capability-authority.md) — actor-independent separation of function, performer, capability and authority.
4. [`04-secure-engineering-foundation.md`](04-secure-engineering-foundation.md) — secure engineering as a cross-cutting property of the method.
5. [`05-universal-engineering-principles.md`](05-universal-engineering-principles.md) — the initial STATE-native universal engineering principles.

The Conceptual layer does not prescribe a specific human organization, AI system, toolchain, operating system or implementation technology.
